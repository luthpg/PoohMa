# Documentation Cross-Consistency & Update Workflow

PoohMa の設計書・ドキュメント群は多面的（データモデル、認証フロー、API一覧、状態管理責務表、セキュリティ境界）に構成されているため、**1箇所の変更が複数セクション・複数ファイルに波及します**。コード変更時は、本ワークフローに従って横断確認を行い、古い仕様の残骸を漏れなく同期してください。

---

## 1. ドキュメント更新チェック手順

1. **計画段階**: 変更内容に関連するドキュメント（要件定義、ER図、API仕様、環境変数、脅威モデル等）の更新要否を事前に特定する。
2. **実装・レビュー段階**: コード変更差分とドキュメントの記述が完全に一致しているかをセルフレビューする。
3. **コミット前**: 更新方針をユーザーに確認・合意した上でドキュメントを更新し、品質検証コマンド（`pnpm verify` 等）を実行する。

---

## 2. ドキュメント横断整合性チェックマトリクス

変更対象のキーワード（関数名、テーブル名、ストレージ種別等）で設計書全体を `grep` し、以下のマトリクスに従って全箇所を同時に更新してください。

| 変更の種類 | 確認・同期すべきドキュメント箇所 |
| :--- | :--- |
| **スキーマ・テーブル構成** | `code-design.md`「4.1 ER概要」「4.2 テーブル定義」、`.ai/domain.md` |
| **Server Function / Convex 関数の追加・削除・改名** | `code-design.md`「7. API設計」「7.6 Server Functions」表、`.ai/architecture.md` |
| **認証イベント・フロー** | `code-design.md`「5.2 認証フロー」「5.6 ログアウトフロー」、`security-model.md`、`.ai/invariants.md` |
| **状態管理・ストレージ** | `code-design.md`「8.4 状態管理表」、`security-model.md`、`.ai/patterns.md` |
| **セキュリティ境界・脅威** | `security-model.md`、`threat-model.md`、`.ai/invariants.md` |
| **データ移行・UID引き継ぎ** | `code-design.md`「4.1 ER概要」「5.2 フロー」「7.1 API表」、`security-model.md`、`.ai/domain.md` |

> **Pitfall**: 設計書の「ある1セクションだけ更新して他のセクションに古い記述が残る」ことが、外部レビュー（CodeRabbit等）で最も頻繁に指摘されるパターンです。必ずプロジェクト全体で一括検索・置換を行ってください。
